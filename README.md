# mr-dan

پلتفرم مشاورهٔ تحصیلی هوشمند.

- پلن معماری، فازها و اسکیل‌ها: [`docs/plan/`](./docs/plan/README.md)
- راهنمای اجرا، حساب‌های دمو و تست دستی فاز ۵.۱: [`docs/usage-phase-5-1.md`](./docs/usage-phase-5-1.md)
- مخزن مرجع (oracle): [`mr-rag`](https://github.com/MostafaRastegar/mr-rag) — کلون محلی در `./mr-rag`، git-ignored

## اجرا

```bash
corepack enable pnpm
pnpm install
cp .env.example .env          # OPENROUTER_API_KEY را پر کن
docker compose up -d          # postgres + chroma
pnpm prisma generate && pnpm prisma migrate dev
pnpm dev                      # http://localhost:3000
```

دادهٔ دموی اختیاری (فقط dev؛ در production اجرا نمی‌شود و idempotent است):

```bash
pnpm tsx scripts/seed-advising.ts   # حساب‌های counselor و student + یک گروه نمونه
```

اسکریپت نام کاربری‌ها و رمز دمو را یک بار در stdout چاپ می‌کند.

وابستگی جدید فاز ۵.۱ فقط `@tabler/icons-react@3.52.0` است (تنها icon set پروژه، pin دقیق بدون `^`). هیچ متغیر محیطی جدیدی اضافه نشده است؛ نام کوکی و TTL نشست ثابت‌اند، نه config.

## ساختار کد

```text
src/
├─ app/<route>/                page.tsx + <x>.vm.tsx + <x>.view.tsx + <area>.actions.ts
│  └─ _components/             route-private vm/view pairs
├─ components/                 providers.tsx (global ConfigProvider only)
├─ utils/                      app-error.ts, server-action.ts, use-form-action.ts
├─ modules/<domain>/           domain, application, infrastructure, presentation
└─ server/                     container.ts, advising-guards.ts
```

لایه‌های دامنه در `src/modules/<domain>/{domain,application,infrastructure,presentation}` دست‌نخورده‌اند؛ این تغییر فقط لایهٔ فرانت است.

صفحات:
- `/` — صفحه اصلی با لینک به چت، پنل دانش و اسناد API
- `/chat` — چتはري streaming با منابع و دکمه-stop
- `/admin/knowledge` — آپلود، لیست، جستجو، حذف اسناد و آمار
- `/api-docs` — اسناد API با Swagger UI (spec در `/api-docs`، spec خام در `/api/openapi`)
- `/login` — ورود با نام کاربری و رمز
- `/register` — ثبت‌نام دانش‌آموز یا مشاور
- `/profile` — مشاهده و ویرایش پروفایل تحصیلی، گروه و مشاور
- `/counselor/students` — پنل مشاور: ساخت گروه و تخصیص دانش‌آموز (فقط مشاور)
- `/dashboard` — داشبورد دانش‌آموز: سلام، تکالیف امروز/فردا، برنامه کلاس‌ها، زمان آزاد، هدف هفته، کتاب پیشنهادی و کیفوری (همه از دیتابیس)
- `/schedule` — برنامه هفتگی: افزودن/ویرایش/حذف سطر (روز، ساعت، درس، معلم، اتاق)
- `/homework` — تکالیف با عنوان، درس، اولویت و deadline (وضعیت انجام/منقضی/امروز/آینده)
- `/study` — تایمر پومودورو ۲۵/۵ + تحلیل زمان و نرخ بهره‌وری
- `/nutrition` — پروفایل فیزیکی، محاسبهٔ BMR/TDEE و برنامهٔ وعده‌های امروز
- `/leisure` — پیشنهاد فراغت و کتاب پیشنهادی

بررسی سلامت:

```bash
curl localhost:3000/api/health
# {"status":"ok","dependencies":{"postgres":"ok","chroma":"ok"}, ...}
```

## احراز هویت و پروفایل

- دو نقش: `student` و `counselor`. ثبت‌نام نقش را انتخاب می‌کند؛ نقش مشاور تا فاز ۵.۴ تأیید ادمین ندارد.
- نشست در Postgres ذخیره می‌شود و مرورگر فقط توکن را در کوکی `mrdan_session` دارد: `httpOnly`، `sameSite=lax`، `path=/`، `secure` فقط در production، TTL هفت روز.
- رمز با `node:crypto` و scrypt هش می‌شود (قالب `scrypt$...`)؛ **رمز خام هرگز ذخیره نمی‌شود**. در DB تنها SHA-256 توکن نشست می‌ماند، نه خود توکن.
- دانش‌آموز پروفایل تحصیلی‌اش (پایه، رشته، مدرسه) را می‌بیند و ویرایش می‌کند؛ تغییر رمز نیازمند رمز فعلی است و سایر نشست‌های همان کاربر را باطل می‌کند.
- مشاور گروه می‌سازد و دانش‌آموز را به گروه خودش تخصیص می‌دهد؛ این تخصیص در یک update اتمی انجام می‌شود (یک گروه و یک مشاور برای هر دانش‌آموز).

## برنامه هفتگی، تکالیف و تایمر مطالعه

- `/schedule` — برنامه هفتگی: افزودن/ویرایش/حذف سطر با روز هفته، ساعت شروع/پایان، درس، معلم و اتاق. دو سطر در یک روز نمی‌توانند با هم تداخل داشته باشد.
- `/homework` — لیست تکالیف با عنوان، درس، اولویت و deadline (روز تقویمی ایران). وضعیت: انجام شده، منقضی شده، امروز یا آینده؛ تکالیف خود را می‌توانید انجام دهید یا حذف کنید.
- `/study` — تایمر پومودورو ۲۵/۵ سمت کلاینت. حالت interval در مرورگر ندارد؛ رفرش صفحه حالت در حال اجرا را از بین می‌برد. وقتی بازه تمرکز تمام شود، صفحه بازبینی ظاهر می‌شود و جلسه فقط با ثبت صریح در فرم ذخیره می‌شود (هیچ چیز به صورت خودکار persistence نمی‌شود).
- تحلیل زمان: نرخ بهره‌وری = مطالعه/(مطالعه+استراحت+اتلاف)؛ با مخرج صفر مقدار ۰ برمی‌گردد و NaN نمی‌شود. رنج ۷ روزه، مرز روز ثابت UTC+۰۳:۳۰، و جمع دقیقه‌ها بر اساس درس.
- مشاور فقط برنامهٔ خویش را می‌بیند و می‌نویسد؛ خواندن سطرهای دانش‌آموزان خود در لایه استفاده است، بدون صفحهٔ UI تا فاز ۵.۴.

درس‌ها فقط از کاتالوگ `src/modules/advising/domain/subjects.ts` انتخاب می‌شوند (slug ثابت + برچسب فارسی). فهرست شامل دروس عمومی (قرآن، دین و زندگی، فارسی، عربی، زبان انگلیسی، ریاضی، علوم تجربی، مطالعات اجتماعی، فرهنگ و هنر)، دروس ریاضی فیزیک (حسابان، هندسه، ریاضی گسسته، آمار و احتمال، فیزیک، شیمی)، علوم تجربی (زیست‌شناسی)، علوم انسانی (ادبیات اختصاصی، تاریخ، جغرافیا، اقتصاد، فلسفه و منطق، روان‌شناسی، جامعه‌شناسی، ریاضی و آمار) و فنی حرفه‌ای (حسابداری، برق، مکانیک، شبکه و نرم‌افزار رایانه) است. مقدار خارج از کاتالوگ با خطای فیلد فارسی رد می‌شود؛ نمودار «مقایسهٔ دروس» فاز ۵.۴ بر همین slug گروه می‌کند.

مشاهدهٔ جزئیات رفتاری: `docs/behaviors/phase-5-2-schedule-homework-study.md`

## تغذیه و اوقات فراغت

- `/nutrition`: شش فیلد فیزیکی (سن، جنسیت، قد، وزن، سطح فعالیت، هدف غذایی)، محاسبهٔ BMR و TDEE و کالری هدف، و برنامهٔ وعده‌های امروز. این فیلدها در `/nutrition` نگهداری می‌شوند، نه در `/profile`.
- `/leisure`: پیشنهاد فراغت بر اساس مطالعهٔ هفت روز اخیر و تکالیف باقی‌مانده، همراه با یک کتاب پیشنهادی از کاتالوگ ثابت.

محاسبه با Mifflin-St Jeor است: BMR از وزن، قد، سن و جنسیت؛ TDEE برابر BMR ضرب در ضریب فعالیت. ضریب‌های فعالیت: کم‌تحرک ۱٫۲، سبک ۱٫۳۷۵، متوسط ۱٫۵۵، فعال ۱٫۷۲۵، خیلی فعال ۱٫۹. هدف غذایی: کاهش وزن ۰٫۸۵، حفظ وزن ۱، افزایش وزن ۱٫۱. کالری هدف هرگز زیر ۱۲۰۰ کالری نمی‌رود.

تقسیم وعده‌ها: صبحانه ۲۵٪، ناهار ۳۵٪، شام ۳۰٪ و باقی‌مانده برای میان‌وعده، تا جمع چهار وعده دقیقاً برابر کالری هدف شود. هر روز یک ردیف `(studentId, dayKey)` دارد و ذخیرهٔ دوبارهٔ همان روز همان ردیف را به‌روز می‌کند؛ برنامه دستی قابل ویرایش نیست.

پیشنهاد فراغت پنج شاخه دارد و اولین شرط برنده است: خستگی بحرانی (۹۰۰ دقیقه در سه روز یا ۲۱۰۰ دقیقه در هفت روز)، بار کاری سنگین (۳ کار عقب‌افتاده یا ۸ کار در انتظار، حتی اگر ساعت مطالعه زیاد باشد)، هفتهٔ پرترافیک (۱۵۰۰ دقیقه در هفته)، تعادل خوب (۶۰۰ دقیقه در هفته با صفر کار عقب‌افتاده) و در غیر این صورت شروع کوچک. فقط ردیف‌های مطالعه در این جمع می‌آیند؛ استراحت و اتلاف حساب نمی‌شوند. کتاب به ترتیب کاتالوگ انتخاب می‌شود: اول تطابق رشته و کد پیشنهاد، سپس کتاب مستقل از رشته.

مشاهدهٔ جزئیات رفتاری: `docs/behaviors/phase-5-3-nutrition-leisure.md`

## داشبورد

- `/dashboard` سرور-رندر است و هر کارت را از دیتابیس می‌خواند — هیچ دادهٔ فیک/هاردکد در `src/app/**` وجود ندارد و `?demo=` حذف شده است.
- سلام و نام کامل از ردیف `User` نشست جاری (نشانweisندهٔ counselor به `/counselor/students` هدایت می‌شود).
- تکالیف امروز/فردا (`Homework`) با دکمهٔ «انجام شد» و دقیقهٔ صرف‌شده (۱–۱۴۴۰).
- برنامه کلاس‌های امروز (`WeeklySchedule`) به بلوک‌های ۵۰/۱۰ دقیقه‌ای (`buildStudyBlocks`) با دکمهٔ تیک.
- زمان آزاد = بیداری − کلاس‌های امروز − اشغال غیرمدرسی − میانگین تکالیف (Clamp ۰).
- هدف هفته: ساعت مطالعه و تعداد تست از `StudyPlan`+`WeeklyGoal`؛ افزایش تست ۱۰-تایی.
- کتاب پیشنهادی (`pickBook`) بر اساس رشته و پیشنهاد سر gardی.
- کیفوری: برنامه غذای امروز و ate slots فقط اگر پروفایل بدنی کامل باشد (`targetCalories`).

مشاهدهٔ جزئیات رفتاری: `docs/behaviors/dashboard.md`

| `/schedule`, `/homework`, `/study` | به `/login` | ۲۰۰ | ۲۰۰ | ۲۰۰ |

مشاور فقط سطرهای برنامه‌نویسیٔ خویش را می‌نویسد (هیچ سطر دانش‌آموز یا دانش‌آموزانِ خویش را نمی‌نویسد); خواندن سطرهای دانش‌آموزان خود در لایه استفاده است، بدون صفحهٔ UI تا فاز ۵.۴.

APIهای محدود پاسخ JSON `{error:{code,message,requestId}}` برمی‌گردند (۴۰۱ یا ۴۰۳). صفحات غیرمجاز به `/login` یا `/profile` ریدایرکت می‌شوند.

ایجاد ادمین فقط از طریق اسکریپت dev است:

```bash
pnpm tsx scripts/create-admin.ts <username>
```

اسکریپت در `production` اجرا نمی‌شود (خطا می‌دهد)، کاربر موجود را به `admin` ارتقا می‌دهد (فقط فیلد `role`، هرگز `passwordHash` را نمی‌トルد) یا کاربر جدید با رمز تولید‌شده می‌سازد که یکبار در stdout چاپ می‌شود. ثبت‌نام فقط نقش `student` و `counselor` می‌پذیرد؛ هرگز `admin` می‌سازد.

نصب ادمین: UI مدیریت وجود ندارد؛ `user:manage` اعلام‌شده است اما استفاده نمی‌شود؛ مالکیت RAG از طریق کاربر وجود ندارد (هر نشست کل داده RAG را می‌بیند).

جزئیات: [`docs/behaviors/access-control-baseline.md`](./docs/behaviors/access-control-baseline.md)

## محدودیت‌ها

- بدون rate limiting یا قفل حساب پس از تلاش‌های ناموفق ورود.
- بدون تأیید ایمیل و بدون بازیابی رمز عبور.
- ثبت‌نام خودکار نقش `counselor` تا فاز ۵.۴ تأیید ادمین ندارد.
- فیلدهای فیزیکی در `/nutrition` نگهداری می‌شوند، نه در `/profile`.
- بانک سؤال، آزمون یا کارنامهٔ کنکور وجود ندارد؛ این بخش از نقشه‌راه حذف شد.
- برنامهٔ وعده تولید می‌شود و دستی قابل ویرایش نیست؛ فقط برنامهٔ امروز نمایش داده می‌شود و تاریخچه ندارد.
- اعداد کالری تخمینی‌اند و جایگزین نظر پزشک نیستند.
- فهرست کتاب‌ها یک کاتالوگ ثابت در کد است و تاریخچهٔ کتاب به‌ازای کاربر وجود ندارد.
- پاک‌سازی نشست‌های منقضی lazy است (هنگام resolve)؛ scheduler وجود ندارد.
- حالت تایمر پومودورو در مرورگر persistence نمی‌شود؛ رفرش صفحه حالت در حال اجرا را از بین می‌برد (هیچ scheduler یا یادآور تلگرام وجود ندارد).
- نمودار/چارت تا فاز ۵.۴ اضافه نمی‌شود؛ تحلیل زمان فقط اعداد و جدول است.
- خواندن سطرهای برنامه‌ریزی دانش‌آموزان توسط مشاور فقط در لایه استفاده است، بدون صفحهٔ UI تا فاز ۵.۴.
- مرز روز برای bucketsUTC+۰۳:۳۰ است (بدون تنظیم منطقه زمانی کاربر).
- فهرست دروس از `FIELDS` চার مقدار پیروی می‌کند (گروه «هنر» وجود ندارد).
- اتصال RAG به دادهٔ مشاوره (مالکیت/visibility اسناد) هنوز انجام نشده است.

## دستورها

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

- lint با `oxlint` است؛ `typescript-eslint` هنوز از TypeScript 7 پشتیبانی نمی‌کند.
- تست معماری (`test/architecture.test.ts`) قواعد لایه‌ها را enforce می‌کند.
- تست یکپارچه (`test/integration.test.ts`) بدون docker gracefully skip می‌شود.
- تست e2e (`tests/e2e/`) با `E2E_ENABLED=true pnpm test:e2e` اجرا می‌شود (نیاز به سرویس‌های زنده).
